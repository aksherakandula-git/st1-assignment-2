Before using AI, I worked with the human-written SmartCare prototype, which stored patient names, practitioner names and appointment times. I also used an enhanced version that stored appointments in a list, represented each appointment using a dictionary, and used functions to book and display appointments. This helped me understand the basic structure of the program before using AI.

AI helped me better understand how the book_appointment() function works, particularly how a dictionary is created and then added to the appointments list using append(). It also helped identify limitations, such as missing validation and the possibility of duplicate bookings. The AI-generated alternative made assumptions that the supplied values were valid because it did not validate empty or unusual inputs.

I did not assume the AI-generated code was correct. I ran the code and tested normal appointments, a blank patient name, duplicate practitioner/time bookings and None values. These tests showed which behaviours worked and which limitations remained. I then made one controlled improvement by adding validation to prevent an empty practitioner name. The remaining engineering work involved testing the program, evaluating AI suggestions, deciding which improvement was appropriate, and verifying that my final change behaved as expected.
